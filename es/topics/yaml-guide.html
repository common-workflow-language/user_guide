2.1. Guía de YAML#

YAML es un formato de archivo diseñado para ser leído tanto por ordenadores como por humanos. Esta guía presenta las características de YAML que son relevantes a la hora de escribir descripciones CWL y archivos de parámetros de entrada.

Nota

Puede saltarse esta sección si ya se siente cómodo con YAML.

2.1.2. Pares clave-valor#

Básicamente, un archivo escrito en YAML consiste en un conjunto de pares clave-valor. Cada par se escribe como key: value, donde el espacio en blanco después del : es obligatorio. Los nombres de las claves en los archivos CWL no deben contener espacios en blanco - camelCase se utiliza para nombres de claves de varias palabras que tienen un significado especial en la especificación CWL y nombres de claves subrayados en caso contrario. Por ejemplo:

first_name: Bilbo
last_name:  Baggins
age_years:  111
home:       Bag End, Hobbiton

El YAML anterior define cuatro claves - first_name, last_name, age_years, y home - con sus cuatro valores respectivos. Los valores pueden ser cadenas de caracteres, numéricos (enteros, coma flotante o representación científica), booleanos (true o false) o tipos anidados más complejos (consulte más abajo).

Los valores pueden ir entre comillas, pero tenga en cuenta que esto puede cambiar la forma en que se interpretan, es decir, "1234" se tratará como una cadena de caracteres, mientras que 1234 se tratará como un número entero. Esta distinción puede ser importante, por ejemplo, cuando se describen los parámetros de un comando: en CWL todas las partes de baseCommand deben ser cadenas de caracteres, por lo que, si desea especificar un valor numérico fijo a un comando, asegúrese de envolver ese valor numérico entre comillas: comandobase: [echo, "42"].

2.1.3. Comentarios#

Puede utilizar # para añadir comentarios a sus archivos CWL y de parámetros. Cualquier carácter a la derecha de # será ignorado por el programa que interprete el YAML. Por ejemplo:

first_name: Bilbo
last_name:  Baggins
age_years:  111
# this line will be ignored by the interpreter
home:       Bag End, Hobbiton # this is ignored too

If there is anything on the line before the comment, be sure to add at least one space before the #!

2.1.4. Maps#

Cuando se describe una herramienta o flujo de trabajo con CWL, suele ser necesario construir representaciones anidadas más complejas. Denominadas maps, estas estructuras jerárquicas se describen en YAML proporcionando pares clave-valor adicionales como valor de cualquier clave. Estos pares (a veces denominados «heredados») se escriben en nuevas líneas bajo la clave a la que pertenecen (el «antecesor»), y deben sangrarse con dos espacios (no se permiten caracteres ⇥tab). Por ejemplo:

cwlVersion: v1.0
class: CommandLineTool
baseCommand: echo
inputs: # this key has an object value
  example_flag: # so does this one
    type: boolean
    inputBinding: # and this one too
      position: 1
      prefix: -f

El YAML anterior ilustra como construir descripciones complejas de objetos anidados de forma relativamente rápida. El mapa inputs contiene una única clave, example_flag, que a su vez contiene dos claves, type y inputBinding, mientras que uno de sus descendentes, inputBinding, contiene otros dos pares clave-valor (position y prefix). Consulte la sección Formaciones para obtener más información sobre cómo proporcionar varios valores/parejas clave-valor para una única clave. Para compararlo con el ejemplo YAML anterior, he aquí una representación gráfica del objeto inputs descrito.

graph TD inputs --> example_flag example_flag --> type type --- bool((boolean)) example_flag --> inputBinding inputBinding --> position inputBinding --> prefix position --- posval((1)) prefix --- prefval(('-f'))

2.1.5. Formaciones#

En determinadas circunstancias, es necesario proporcionar varios valores u objetos para una única clave. Como ya hemos visto en la sección Mapas anterior, es posible asignar más de una pareja clave-valor a una única clave. Sin embargo, también es posible definir múltiples valores para una clave sin tener que proporcionar una clave única para cada valor. Podemos conseguirlo con una formación, donde cada valor se define en su propia línea y precedido por -. Por ejemplo:

touchfiles:
  - foo.txt
  - bar.dat
  - baz.txt

y un ejemplo más complejo que combina mapas y formaciones:

exclusive_parameters:
  type:
    - type: record
      name: itemC
      fields:
        itemC:
          type: string
          inputBinding:
            prefix: -C
    - type: record
      name: itemD
      fields:
        itemD:
          type: string
          inputBinding:
            prefix: -D

2.1.6. Estilo JSON#

YAML se basa en Notación de Objeto JavaScript (JSON). Los mapas y las formaciones también pueden definirse en YAML utilizando la sintaxis JSON nativa. Por ejemplo:

touchfiles: [foo.txt, bar.dat, baz.txt] # equivalent to first Arrays example

y:

# equivalent to the `inputs` example in "Maps" above
inputs: {example_flag: {type: boolean, inputBinding: {position: 1, prefix: -f}}}

Native JSON can be useful in indicating where a field is intentionally left empty (such as [] for an empty array), as well as where it makes more sense for the values to be located on the same line (For example, when providing option flags and their values in a shell command). However, as the second example above shows, it can severely affect the readability of a YAML file, and should be used sparingly.
