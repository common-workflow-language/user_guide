2.8. Tipos personalizados#

A veces es posible que desee escribir sus propios tipos personalizados para su uso y reutilización en descripciones CWL. El uso de estos tipos personalizados puede reducir la redundancia entre múltiples descripciones que todos utilizan el mismo tipo, y también permite la personalización/configuración adicional de una herramienta/análisis sin la necesidad de trapichear directamente con la descripción de CWL.

El siguiente ejemplo es una descripción de CWL de la herramienta del formato de conversión biom para convertir un archivo de tabla de bioma estándar al formato hdf5.

custom-types.cwl#
#!/usr/bin/env cwl-runner
cwlVersion: v1.2
class: CommandLineTool

requirements:
  InlineJavascriptRequirement: {}
  ResourceRequirement:
    coresMax: 1
    ramMin: 100  # just a default, could be lowered
  SchemaDefRequirement:
    types:
      - $import: biom-convert-table.yaml

hints:
  DockerRequirement:
    dockerPull: 'quay.io/biocontainers/biom-format:2.1.15'
  SoftwareRequirement:
    packages:
      biom-format:
        specs: [ "https://doi.org/10.1186/2047-217X-1-7" ]
        version: [ "2.1.15" ]

inputs:
  biom:
    type: File
    format: edam:format_3746  # BIOM
    inputBinding:
      prefix: --input-fp
  table_type:
    type: biom-convert-table.yaml#table_type
    inputBinding:
      prefix: --table-type

  header_key:
    type: string?
    doc: |
      The observation metadata to include from the input BIOM table file when
      creating a tsv table file. By default no observation metadata will be
      included.
    inputBinding:
      prefix: --header-key

baseCommand: [ biom, convert ]

arguments:
  - valueFrom: $(inputs.biom.nameroot).hdf5
    prefix: --output-fp
  - --to-hdf5

outputs:
  result:
    type: File
    outputBinding: { glob: "$(inputs.biom.nameroot)*" }

$namespaces:
  edam: http://edamontology.org/
  s: https://schema.org/

$schemas:
  - http://edamontology.org/EDAM_1.16.owl
  - https://schema.org/version/latest/schemaorg-current-http.rdf

s:license: https://spdx.org/licenses/Apache-2.0
s:copyrightHolder: "EMBL - European Bioinformatics Institute"
custom-types.yml#
biom:
    class: File
    format: http://edamontology.org/format_3746
    path: rich_sparse_otu_table.biom
table_type: OTU table

Nota: Para seguir el ejemplo a continuación, necesita descargar el archivo de entrada de ejemplo, rich_sparse_otu_table.biom por ejemplo mediante wget:

$ wget https://github.com/common-workflow-language/user_guide/raw/main/src/_includes/cwl/custom-types/rich_sparse_otu_table.biom

En la línea 29, en inputs:table_type, es importado como objeto personalizado una lista de opciones de tabla concedidas para ser utilizadas en la conversión de tabla:

inputs:
  biom:
    type: File
    format: edam:format_3746  # BIOM
    inputBinding:
      prefix: --input-fp
  table_type:
    type: biom-convert-table.yaml#table_type
    inputBinding:
      prefix: --table-type

La referencia a un tipo personalizado es una combinación del nombre del archivo en el que se define el objeto (biom-convert-table.yaml) y el nombre del objeto dentro de ese archivo (table_type) que define el tipo personalizado. En este caso, la formación symbols del archivo importado biom-convert-table.yaml define las opciones de tabla permitidas. Por ejemplo, en custom-types.yml, pasamos OTU table como input que indica a la herramienta que cree una tabla OTU en formato hdf5.

El contenido del archivo YAML que describe el tipo personalizado de proporciona a continuación:

biom-convert-table.yaml#
type: enum
name: table_type
label: The type of the table to produce
symbols:
  - OTU table
  - Pathway table
  - Function table
  - Ortholog table
  - Gene table
  - Metabolite table
  - Taxon table
  - Table

Para que el tipo personalizado se utilice en la descripción CWL, debe ser importado. Las importaciones se describen en requirements:SchemaDefRequirement, como en el ejemplo de descripción custom-types.cwl:

requirements:
  InlineJavascriptRequirement: {}
  ResourceRequirement:
    coresMax: 1
    ramMin: 100
  SchemaDefRequirement:
    types:
      - $import: biom-convert-table.yaml

Tenga en cuenta también que el autor de esta descripción de CWL también ha incluido ResourceRequirements, especificando la cantidad mínima de RAM y la cantidad de núcleos necesarios para que la herramienta se ejecute correctamente, así como detalles de la versión del software en la que se escribió la metada útil. Estas características se examinan más adelante en otros capítulos de esta guía de usuario.
